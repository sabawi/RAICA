# DESIGN: Data-Charting — plotting REAL datasets the query asks for

**Status:** Design draft (2026-07-19). No implementation yet. Isolated on branch `feature/data-charts`
(worktree `RAICA-datacharts`, off `main@521d6f5`). Prod `main` untouched; back-out = drop the branch.
**Owner:** RAICA deep-research pipeline.
**Relationship:** generalizes the stock-only inline-chart path (`comprehensive_stock_analyzer` → `[[chart:]]`
markers, rendered by NewX chart-cards) to **arbitrary numeric datasets** a query asks to plot.

---

## 1. Motivation (evidence)

Prod `post/5955` — *"@Ask make a chart plotting the reported yearly crimes in the USA since 1970s"* —
returned **reply#559: a text-only DR answer with zero charts.** Rich qualitative narrative ("rose through
the 70s–80s, peaked early 1990s, fell 49% 1993–2022") but **no numeric series was ever extracted**, so there
was nothing to plot.

Root cause is architectural, not a bug: **today's charts are a side-effect of one tool.**
`comprehensive_stock_analyzer` fetches yfinance OHLCV, renders PNGs, uploads them, and embeds `[[chart:…]]`
markers into its text output; synthesis merely reproduces those markers. **There is no general
"the user asked for a chart → acquire a data series → render it" path.** The planner only advertises
`comprehensive_stock_analyzer` as a structured-data source (`engine.py` planner prompt).

An `analytical_visualizer` tool exists but is the wrong foundation: prompt-only, **data generated by
LLM-written code** (fabrication risk), base64 output (not the trusted card path), and **not wired into DR**.

## 2. The load-bearing principle

The stock charts are trusted because they are **deterministic from real data (yfinance)**. A general
"chart anything" that lets the model supply the numbers produces **authoritative-looking fabricated
charts — strictly worse than an honest text answer.** So the entire feature is governed by three
**non-negotiable hard rules**:

1. **NUMBERS-BY-REFERENCE.** The LLM NEVER generates or transcribes a data point. A dataset tool stores the
   real series out-of-band keyed by an **ID**; the LLM sees a compact **digest**, SELECTS a dataset by ID,
   and only COMMENTS on it; the **renderer plots the stored payload**. (Exact mirror of
   yfinance-payload → `chart_generator` renders → LLM narrates.)
2. **FAIL-CLOSED.** No trusted dataset that meets scrutiny → **no chart** (never an "illustrative" one).
3. **DIGEST-TO-LLM.** Full series stored out-of-band; the LLM sees only schema, units, source, date range,
   N points, a few sampled values, and provenance — never the raw table dumped into context.

## 3. The spine: a DATASET SOURCE BLOCK as first-class evidence

The key design decision (user-approved): a dataset is **another evidence modality** flowing through the
**same** plan → gather → grade → verify → attribute → primary-vs-secondary → synthesis machinery as text
blocks — not a parallel system. This maximally reuses the battle-tested pipeline and keeps one trust model.

Today an evidence item is (`engine.py:518`):

```python
{"sub_question_id", "question", "source", "query", "round", "content", "urls", "chars"}
```

A **dataset evidence item** uses the SAME dict shape — its `content` is the **digest text** (so all existing
grade/verify/coverage code reads it unchanged) — plus dataset-specific fields the digest also encodes and the
renderer needs:

```python
{ ...same keys...,
  "modality": "dataset",              # marks this block as numeric (text blocks omit / "text")
  "dataset_id": "ds_ab12cd",          # handle into the out-of-band payload store
  "series_meta": {                    # ALSO rendered into `content` as the human digest
     "title": "US violent crime rate (per 100k)", "source": "FBI UCR/CDE",
     "url": "https://cde.ucr.cjis.gov/…", "retrieved": "2026-07-19",
     "measure": "violent_crime_rate", "unit": "per_100k", "geo": "US-national",
     "x": {"name": "year", "type": "temporal", "min": 1979, "max": 2024, "n": 46},
     "y": {"name": "rate", "type": "quantitative"},
     "methodology": "SRS 1979–2020; NIBRS 2021–", "discontinuities": [{"at": 2021, "note": "SRS→NIBRS"}],
     "sample": [[1979, 548.9], [1991, 758.2], [2020, 398.5], [2024, 364.4]] }}
```

The **payload store** (out-of-band, keyed by `dataset_id`) holds the full `[[x,y], …]` series (+ multi-series).
Local, per-run, TTL'd — same spirit as `chart_publisher._url_cache`. The LLM sees `content`/`series_meta`;
the renderer reads the payload. **The LLM can select and sanity-check but cannot reach the raw numbers to
retype them.**

## 5. The `search_datasets()` tool family

Per the acquisition decision: **curated authoritative data APIs + catalog search** (deterministic,
"yfinance-for-stats"), NOT generic web-table scraping (garbling risk = worse than no chart).

```
search_datasets(spec) =
    search_data_sources(spec)      # map chart_spec → candidate authoritative datasets (catalog search)
  → enumerate_relevant_sources()   # rank; tier by EXTRACTION FIDELITY (structured API > CSV > HTML table)
  → extract_dataset(source)        # pull the real series via the source's API/CSV → store payload, emit digest
```

**Extraction-fidelity tiering** (new trust dimension): a structured API response can't be garbled the way a
scraped table can, so retrieval fidelity ranks alongside publisher reputation when picking the primary source.

**Initial curated adapters** (each a thin, testable client returning a normalized series + meta):
- **MVP: FBI Crime Data Explorer (CDE) API** — directly serves the `post/5955` case with a clean series and
  the SRS/NIBRS methodology metadata (so the discontinuity is *known*, not guessed).
- Next: FRED (economics), World Bank, Our World in Data, Census. Each added behind config; absent adapter →
  that topic simply isn't chartable yet (fail-closed).

## 6. `data_chart_generator` (new, general)

Analog of `chart_generator.py` but domain-free: `line` / `bar` / `scatter`, NewX-styled (reuse the palette /
`_style` conventions), deterministic from a payload + `series_meta`. Renders: title, axis labels+units,
source annotation, and **discontinuity markers/segments** from `series_meta.discontinuities`. Multi-series
overlay only when comparability passed. Returns PNG bytes → `chart_publisher.get_or_publish_chart`.

## 7. Two rollout flows (MVP → full)

- **Increment A — render-at-gather (single series), reuses EVERYTHING.** The dataset tool renders a default
  chart for the extracted series and embeds a `[[chart:url]]` marker in its digest `content`, exactly like the
  stock analyzer. Zero new marker type; zero synthesis change beyond reproduce-the-marker. Delivers
  *"chart yearly crimes since 1970s"* end-to-end. **This is the MVP.**
- **Increment B — render-at-synthesis (relationships / multi-series).** For *"plot X vs Y"* the LLM must pair
  two datasets, so no chart exists at gather time. Tool stores payloads + digests only; synthesis emits a new
  `[[datachart:ids=…|type=…|x=…|y=…]]` marker; a post-synthesis render pass loads the payloads by ID, renders,
  uploads, and rewrites it to `[[chart:url]]`. Still numbers-by-reference (LLM supplies IDs + framing, never
  numbers). Built only after A is proven.

## 8. Config (all OFF by default; env/YAML tunable)

`deep_research.data_charts`: `enabled` (master, default **false**), `sources.allowed` (curated adapter list,
MVP `[fbi_cde]`), `max_datasets_per_response`, `payload_ttl_seconds`, `min_source_tier`, `render` (size, dpi).
Nothing activates until `enabled: true`; with it false the pipeline behaves exactly as today.

## 9. Incremental build plan (small, reversible, each committed on the branch)

1. **Contract + payload store + digest formatter** — pure module, unit-tested, no pipeline wiring.
2. **`data_chart_generator`** — render line/bar/scatter from a payload; offline PNG smoke tests (like
   `test_event_charts.py`).
3. **One adapter (FBI CDE)** behind `search_datasets` — real fetch → payload + digest; offline test on a
   cached response (no network in CI).
4. **Increment A wiring** — planner source + Phase-1 `chart_spec` + render-at-gather marker; behind `enabled`.
   End-to-end local test of the crime query.
5. **Verify additions** — comparability + discontinuity directives; re-run benchmark tiers.
6. (Later) **Increment B** — LLM-composed multi-series.

Each step: `node/py_compile` + unit tests + commit on `feature/data-charts`. Merge to `main` only after the
crime case works end-to-end and Tier-0/1 pass. No prod restart until merge.

## 10. Open questions / risks

- **Adapter coverage vs generality.** Curated APIs mean many topics won't chart at MVP (fail-closed). Accept
  narrow-but-correct first; widen adapters over time.
- **Catalog search quality.** Mapping a free-text chart_spec to the right dataset/series id (e.g. FRED series
  code) is itself a retrieval problem — may need an LLM-ranked catalog lookup, still numbers-by-reference.
- **Comparability false-negatives.** Being strict may decline legitimate overlays; start strict, loosen with
  evidence.
- **Payload store lifetime / concurrency** — per-run, TTL'd, keyed by id; mirror `chart_publisher` cache.

## 11. Back-out

`main` and the running prod RAICA are never touched until an explicit, benchmarked merge.
